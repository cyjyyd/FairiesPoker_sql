# 出牌特效设计与接入

## 视觉方向

与「羽翼牌组」插画使用相同的金色光尘、翡翠柔光和象牙白。新增纹理由 C# 程序生成，不依赖电影或其他游戏素材，没有新增提取音效、全屏闪白或相机震动。

| 牌型 | 表现 | 时长 |
| --- | --- | --- |
| 顺子 | 金色星芒沿弧线扫过，翡翠细光跟随 | 1.1 秒 |
| 连对 | 五组成对金色仙尘旋涡依次聚合，细粉尘光线串联，最后散落淡出 | 1.1 秒 |
| 飞机 | 金色仙尘勾勒跃动双翼，沿弧线飞过牌桌，留下逐渐扩散的粉尘尾迹 | 1.45 秒 |
| 炸弹 | 花苞聚光后绽放，花瓣与冲击环向外展开 | 1.25 秒 |
| 王炸 | 双层光环、更多花瓣与五点星冠 | 1.45 秒 |

飞机和连对完全使用金色仙尘：颜色仅在琥珀金、暖金和香槟金之间变化，使用细颗粒、柔光及少量闪点，不再绘制实体牌形、叶瓣或翡翠色粒子。形状由离散粉尘聚合形成，粒子数量固定，不改变原有时长或出牌事件。

## 架构与生命周期

- PlayEffectMapping 分别映射单机 Guize 和联机 CardType，禁止直接互相强制转换；单机所有飞机变体归为同一表现。
- 单机仅在 MovePai 接受出牌时触发；联机仅在成功出牌广播时触发，拒绝响应、选牌、提示、不出不触发。
- PlayEffectManager 不提供游戏完成回调，不读写规则、倍率、手牌或网络状态，也不加入现有 AnimationManager。
- 最多同时保留三个效果；新的效果替换最旧的效果。每个效果都有固定寿命，长帧仍会正常回收。
- ScreenBase.UpdatePresentation 在覆盖弹窗时继续更新装饰效果；只有顶部屏幕更新玩法及输入。结算不等待装饰特效。
- 新局及服务端发牌清空效果，离开牌桌释放自有纹理；牌桌 UI 在效果上层绘制。
- 使用正常 SpriteBatch 混合，无额外着色器或内容管线依赖，适配现有虚拟坐标。

## 预览

主菜单下方选择「特效预览」，点击任意牌型重播，数字键 1–5 切换，空格暂停或继续。预览使用中性程序牌面，无需登录、连接服务器或改动设置文件。

也可在桌面客户端启动时传入 --effects-preview；--about 可直接查看关于页面。两个参数不改变保存的配置。

## 验证

自动化测试覆盖单机与联机数值冲突、飞机变体、普通牌不触发、并发上限、长帧回收、重复清理，以及结算覆盖层下只更新表现而不推进后台玩法。

手工检查：三家分别出牌；非法出牌和不出；炸弹作为最后一手；快速连续广播；结算后重开；切换主题及窗口尺寸。Android 真机帧率与网络多客户端回归需要单独验证。

## 范围

本次没有增加牌型规则。联机原有牌型支持范围继续由服务端和共享协议决定；特效不会使原本不支持的飞机带牌成为合法出牌。旧 WinForms 客户端同步声明与插画，出牌特效在 MonoGame 客户端实现。

## 可重复的渲染检查

tools/VisualSmoke 使用客户端自己的 GraphicsDevice 与屏幕类导出关于页面和五种特效到 artifacts/visual-smoke。它不保存玩家配置，预览使用真实特效管理器，在固定时间点暂停以方便比较。

~~~powershell
dotnet run --project tools/VisualSmoke/VisualSmoke.csproj -- .
~~~

该工具需要可用的桌面 OpenGL 上下文，但不依赖桌面截图、登录或服务器。客户端不消费 XNB 内容，已移除无用的 MGCB 构建依赖；标准解决方案构建与 Visual Studio F5 无需额外的内容工具命令覆盖。
